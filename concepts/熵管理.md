# 熵管理

> Garbage Collection for AI-generated code。熵不会自己消失，必须主动对抗。

## 概念 (Concept)

熵管理是指对AI生成代码和文档的持续清理——定期扫描不一致、违规和冗余，确保清理速度跟上生成速度。

## 价值 (Value)

### 为什么重要

- AI生成速度快，但质量参差不齐
- 不主动清理，项目会逐渐腐烂
- 可持续性：生成和清理必须平衡

### 解决的问题

- 文档不一致（AI改了代码没改文档）
- 架构违规（AI不知道某些约定）
- 冗余代码（AI重新实现已有功能）

## 用法 (Usage)

### OpenAI 的做法

一开始团队每周五花 20% 的时间手动清理 AI 生成物中的低质量代码。后来自动化了——后台 Agent 定期扫描，找文档不一致、架构违规和冗余代码，自动提交清理 PR。

### Carlini 的做法

在 C 编译器项目中，专门有 Agent 负责"去重"——LLM 生成的代码经常重新实现已有功能。

## 原理 (Principle)

### 为什么有效

熵增是自然趋势。AI生成的内容天然有熵：
- 重复生成相似功能
- 文档和代码不同步
- 风格不一致

只有主动对抗熵增，才能维持系统健康。

### 类比

- 内存泄漏需要垃圾回收
- 房间需要定期打扫
- 代码库需要定期重构

## 心法 (Best Practices)

- 清理速度必须 >= 生成速度
- 自动化优于手动
- 后台运行，不打扰主线工作
- 定期审查清理 Agent 的判断标准
