# LLM Wiki方法论

## 概念
Andrej Karpathy 提出的知识管理方法论：**知识只编译一次，持续维护复用**。将知识存储为相互链接的 markdown 文件，形成可复利增长的知识库。与传统 RAG（每次查询重新检索理解）相反，Wiki 一次编译知识，后续查询直接使用已建立的网络。

## 价值
| 对比维度 | RAG | LLM Wiki |
|---------|-----|----------|
| 交叉引用 | 每次重新发现 | **已建立，直接使用** |
| 矛盾处理 | 每次重新检测 | **已标记，已知问题** |
| 综合质量 | 每次重新合成 | **反映所有摄入内容** |
| 知识累积 | 无累积 | **复利增长** |

核心收益：
- **复利效应** — 单一来源可触发 5-15 页面更新，知识网络自动扩展
- **一致性** — SCHEMA.md 统一规则，标签体系可控
- **可追溯** — log.md 记录所有变更历史
- **Obsidian 兼容** — 直接作为 vault 使用，Graph View 可视化

## 用法

### 三层架构
```
wiki/
├── SCHEMA.md      ← Layer 3: 规约层（约定、标签体系）
├── index.md       ← 内容目录（快速定位）
├── log.md         ← 操作日志（追溯历史）
│
├── raw/           ← Layer 1: 原始层（不可修改）
│   ├── articles/    网页文章
│   ├── papers/      PDF、arxiv 论文
│   ├── transcripts/ 会议记录
│   └── assets/      图片
│
├── entities/      ← Layer 2: 实体页（人、组织）
├── concepts/      ← Layer 2: 概念页（方法论）
├── comparisons/   ← Layer 2: 对比分析
└── queries/       ← Layer 2: 有价值的查询结果
```

### 三大核心操作

#### 1. Ingest（摄入）
```
① 捕获原始来源 → raw/
② 与用户讨论要点
③ 检查已有页面（避免重复）
④ 创建/更新 wiki 页面（≥2 出链）
⑤ 更新 index.md + log.md
⑥ 报告变更
```

#### 2. Query（查询）
```
① 读 index.md 定位相关页面
② 大 wiki 用 search_files 补充
③ 读相关页面
④ 综合 → 回答（引用来源）
⑤ 有价值答案 → queries/
⑥ 更新 log.md
```

#### 3. Lint（审计）
| 检查项 | 说明 |
|--------|------|
| 孤儿页面 | 无入链的页面 |
| 断链 | wikilink 指向不存在页面 |
| 索引完整 | 所有页面在 index.md |
| frontmatter | 必需字段齐全 |
| 陈旧内容 | updated > 90 天 |
| 矛盾 | 同主题页面冲突 |
| 页面尺寸 | >200 行需拆分 |

### 概念页结构：五步认知法
```markdown
## 概念
什么是 X？定义、本质。

## 价值
为什么重要？解决什么问题？

## 用法
如何使用？步骤、案例。

## 原理
为什么有效？底层机制。

## 心法
实践要点、避坑指南。
```

## 原理

### 为什么是三层？
- **Layer 1 不可修改**：保留原始证据，wiki 页面是"解读"而非"替换"
- **Layer 2 Agent 控制**：摘要、交叉引用是 Agent 强项，人类只需掌舵
- **Layer 3 约定驱动**：统一规则防止熵增（标签噪音、格式混乱）

### 为什么复利增长？
每个新来源摄入时：
1. 检查已有页面 → 发现关联
2. 更新关联页面 → 扩展网络
3. 添加交叉引用 → 增强密度

知识网络像神经网络：每个新节点连接已有节点，整体价值随连接数指数增长。

### 为什么比 RAG 好？
RAG 是"每次从头理解"，Wiki 是"一次编译持续使用"。类比：
- RAG = 每次做饭从头买菜
- Wiki = 超市货架已备好，直接取用

## 心法

### 页面阈值
| 情况 | 动作 |
|------|------|
| 2+ 来源提及 / 单来源核心 | ✅ 创建页面 |
| 已有相关页面 | ➕ 添加信息 |
| 过路提及 | ❌ 不创建 |
| >200 行 | 🔀 拆分 |

### 必须做到
- 每页 ≥2 个 `[[wikilinks]]`
- 新页面加入 index.md
- 每次操作写 log.md
- 先读 SCHEMA + index + log 再操作

### 常见陷阱
| 陷阱 | 后果 |
|------|------|
| 修改 raw/ | 丢失证据 |
| 不先定位 | 重复页面 |
| 不更新 index/log | wiki 退化 |
| 孤岛页面 | 不可见 |
| 自由标签 | 噪音失控 |

### 人机分工
| 人类 | Agent |
|------|-------|
| 确定领域 | 摘要总结 |
| 选择来源 | 交叉引用 |
| 审查矛盾 | 创建页面 |
| 维护 SCHEMA | 维护 index/log |
