# 想法记录模板

> 个人想法/灵感/洞见的记录规范。用于捕捉和沉淀自己的思考成果。

## 概念 (Concept)

想法记录是将零散的灵感、洞见、反思转化为结构化知识的过程。区别于读书笔记（来源外部），想法记录源于自我思考。

## 价值 (Value)

### 为什么记录想法

- 防止灵感流失——好想法稍纵即逝
- 促进深度思考——写下来迫使理清逻辑
- 构建个人智慧库——可检索、可复用、可迭代
- 发现思维模式——回顾时可看到自己的认知演进

### 与读书笔记的区别

| 类型 | 目录 | sources | 来源 | 目的 |
|------|------|---------|------|------|
| 读书笔记 | `entities/` 或 `concepts/` | 有来源 | 书籍、论文 | 内化外部知识 |
| 个人想法 | `concepts/` | 留空 | 自我思考 | 沉淀自己的洞见 |

## 用法 (Usage)

### Frontmatter 格式

```yaml
---
title: 想法的名称
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: concept
tags: [concept, thinking, <主题标签>]
sources: []  # 个人想法留空
---
```

### 正文结构（五步认知法）

```markdown
# 想法的名称

## 概念 (Concept)
一句话定义这个想法是什么。

## 价值 (Value)
- 这个想法为什么重要
- 解决了什么问题
- 与其他概念的关联 [[wikilinks]]

## 用法 (Usage)
### 应用场景
- 怎么用这个想法
- 具体举例

## 原理 (Principle)
- 背后逻辑是什么
- 为什么会有效

## 心法 (Best Practices)
- 关键注意事项
- 适用边界
- 常见误区

## Cross-references
- [[相关概念1]]
- [[相关概念2]]
```

### 命名规则

文件名用小写+连字符：
- `insight-about-x.md`
- `reflection-on-y.md`
- `my-theory-of-z.md`

## 原理 (Principle)

### 五步认知法的逻辑

五步结构对应认知深化的层次：
1. **概念** → 是什么（定义层）
2. **价值** → 为什么重要（意义层）
3. **用法** → 怎么用（实践层）
4. **原理** → 为什么有效（机理层）
5. **心法** → 注意什么（边界层）

### wikilinks 的作用

想法不是孤立的。通过 `[[wikilinks]]`：
- 与已有知识建立连接
- 后续检索时可发现关联
- 形成知识网络而非碎片堆

## 心法 (Best Practices)

### 记什么

- 灵光一闪的洞见
- 反复思考后的结论
- 对某事的独特理解
- 方法论的创新应用
- 对已有概念的个人延伸

### 不记什么

- 情绪发泄（用日记而非 wiki）
- 临时想法（太琐碎，不值得结构化）
- 他人观点的重复（那是读书笔记）

### 想法迭代

想法可以更新：
- 新的例子 → 添加到「用法」
- 新的关联 → 添加 wikilinks
- 观点修正 → 更新「概念」或「原理」
- 更新时 bump `updated` 日期

### 页面阈值

参考 SCHEMA.md：
- 一次想法 → 直接记录
- 同主题多次想法 → 合并到同一页面
- 页面超过 ~200 行 → 拆分子主题
