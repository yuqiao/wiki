# 三层记忆

> Hermes Agent的记忆架构：从金鱼到老友。三层各司其职，用SQLite + FTS5索引存储，按需检索而不是全量加载。

## 概念 (Concept)

大多数AI聊天工具的记忆像金鱼，上一轮说的话下一轮就忘了。Hermes的目标是做一个老友：记得你说过什么，知道你是什么样的人，还学会了你做事的方式。

三层记忆回答三个不同的问题：
1. **会话记忆**：发生了什么？
2. **持久记忆**：你是谁？
3. **Skill记忆**：怎么做事？

## 价值 (Value)

### 为什么重要

- 让Agent有跨会话的连续性
- 不需要每次重新解释背景
- 经验可以沉淀为方法论

### 解决的问题

| 问题 | 传统方案 | 三层记忆方案 |
|------|----------|--------------|
| 上下文爆炸 | 全量加载，撑不下 | 按需检索，恒定占用 |
| 信息过载 | 什么都在，什么都找不到 | 关键词精准匹配 |
| 无持久性 | 开新对话就清空 | 跨会话保持 |

### 对比Claude Code

| 维度 | Claude Code | Hermes |
|------|-------------|--------|
| 记忆格式 | CLAUDE.md + auto-memory文本 | SQLite + FTS5 + Skill文件 |
| 写入方式 | 手动写，半自动 | 全自动写入，人可覆盖 |
| 检索方式 | 启动时全量加载 | 按需FTS5检索 |
| 记忆粒度 | 项目级 | 全局级 + 项目级 |
| 用户建模 | 无 | Honcho自动推理 |

## 用法 (Usage)

### 第一层：会话记忆

- 存储：SQLite数据库
- 索引：FTS5全文搜索
- 内容：对话内容、工具调用、返回结果
- 特点：按需检索，不是全量加载

### 第二层：持久记忆

- 存储：SQLite
- 管理：memory工具
- 内容：编码偏好、项目结构习惯、常用工具链、工作时间规律
- 特点：跨会话保持，不会因为开新对话就丢失

### 第三层：Skill记忆

- 存储：~/.hermes/skills/ 目录下的markdown文件
- 内容：方法论、操作规范
- 特点：可读可编辑，Agent自创建自改进

## 原理 (Principle)

### 对应认知科学

三层记忆对应人类大脑的三种记忆类型：

| Hermes记忆层 | 认知科学对应 | 功能 |
|---------------|--------------|------|
| 会话记忆 | 情景记忆（海马体） | 发生了什么 |
| 持久记忆 | 语义记忆 | 你是谁，世界是什么样的 |
| Skill记忆 | 程序性记忆 | 怎么做事 |

### 学骑自行车的类比

你记得上次摔了（情景）→ 你知道重心要放低（语义）→ 你的身体会自动保持平衡（程序性）。

### 协作示例

你说「帮我部署这个项目」：
1. Hermes用FTS5搜索会话记忆，找到上次部署时的端口冲突问题（情景）
2. 查持久记忆，知道你用的是阿里云ECS、Nginx反向代理（语义）
3. 加载deployment-checklist Skill，按验证过的步骤执行（程序性）

## 心法 (Best Practices)

### 什么该记

- 用户偏好和习惯（代码风格、工具选择、沟通方式）
- 项目上下文（架构决策、技术栈、文件结构）
- 验证过的解决方案（Skill）
- 重复出现的模式

### 什么不该记

- 一次性任务的细节（帮我写生日贺词）
- 过时的信息（三个月前的API版本号）
- 错误的推断（需要清理）
- 敏感信息（密码、密钥）

### 定期维护

Hermes目前没有自动过期机制，建议：
- 定期检查 ~/.hermes/ 目录大小
- 清理过时的Skill文件
- 修正错误的推断

### 便携性

整个 ~/.hermes/ 目录就是全部状态：
- 备份到U盘，换电脑继续用
- Docker部署时挂载目录保持状态
- 多设备之间可定期拷贝同步
