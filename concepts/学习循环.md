# 学习循环

> Hermes Agent的核心机制：Agent自己给自己造缰绳。五个环节形成一个持续改进的飞轮。

## 概念 (Concept)

学习循环是Hermes Agent的"心脏"。每次完成一个任务，它会自动复盘：该记住什么、该提炼什么Skill、现有Skill需不需要优化。这个循环是持续运转的，不需要你手动触发。

## 价值 (Value)

### 为什么重要

- 让Agent从经验中自动学习
- 不需要人持续维护配置
- 用得越多，越好用

### 解决的问题

传统AI工具的记忆是对话记录的堆积，会越来越长最终溢出。学习循环的记忆是经验的蒸馏，可以一直用下去。

### 关键区别

| 传统记忆 | Hermes学习循环 |
|----------|----------------|
| 录像带 | 笔记本 |
| 越来越长 | 按需检索 |
| 撑不下为止 | 可以用几年 |

## 用法 (Usage)

### 五个环节

```
策划记忆 → 创建Skill → Skill自改进 → FTS5召回 → 用户建模
```

每个环节有因果关系：记忆提供Skill创建的素材，Skill在使用中积累反馈触发自改进，FTS5让历史经验被精准召回，用户建模把这些碎片拼成一幅完整的画。

### 环节详解

| 环节 | 功能 | 实现方式 |
|------|------|----------|
| 策划记忆 | 决定哪些信息值得记住 | SQLite + FTS5 + nudge机制 |
| 创建Skill | 提炼解决方案为Skill | ~/.hermes/skills/ 目录 |
| Skill自改进 | 根据反馈修改Skill | 自动更新markdown文件 |
| FTS5召回 | 搜索相关历史 | 按需检索而非全量加载 |
| 用户建模 | 推理用户特征 | Honcho辩证建模 |

## 原理 (Principle)

### 飞轮效应

五个环节组成一个正反馈循环：
- 记忆喂养Skill
- Skill使用中产生新记忆
- 新记忆触发Skill改进
- 改进后的Skill产生更好的结果
- 更好的结果让用户建模更准确

用得越多，每个环节都在变强，而且是同时变强。

### 对比Mitchell手动方式

| 维度 | Mitchell手动 | Hermes自动 |
|------|--------------|------------|
| 规则来源 | 人观察到问题后手写 | Agent自己从反馈中提炼 |
| 存储位置 | CLAUDE.md（单文件） | 多Skill + 记忆数据库 |
| 触发改进 | 人记得才会加 | 每次使用后自动评估 |
| 跨项目迁移 | 手动复制CLAUDE.md | Skill全局生效 |
| 改进速度 | 取决于人的勤快程度 | 持续自动 |

## 心法 (Best Practices)

### 使用频率决定效果

- 一周只用一两次：改进很慢
- 每天都用：飞轮转得非常快
- 建议：部署在$5 VPS上24/7运行，让它持续积累

### 反馈质量决定进化方向

- 反馈越清晰，进化越精准
- 「不太对」不如「这里应该这样改」
- 好的反馈 = 好的进化方向

### 定期审查

- 看看 ~/.hermes/skills/ 下有哪些Skill
- 删掉不合适的，修正错误的推断
- 就像整理笔记本，偶尔翻翻会发现需要更新的内容
