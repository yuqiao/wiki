# Builder 生成器模式

## 概念 (Concept)

将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。Builder模式描述了生成器（builder）和导向器（director）之间的关系。

## 价值 (Value)

### 解决什么问题

- 创建复杂对象的算法应独立于组成部分及其装配方式
- 构造过程必须允许被构造对象有不同表示
- RTF阅读器需要转换为多种正文格式，但转换数目无限

### 带来什么收益

1. **改变内部表示**：Builder提供抽象接口，隐藏产品表示和内部结构
2. **分离构造和表示**：提高模块性，客户不需知道定义产品内部结构的类的所有信息
3. **精细控制构造**：在导向者控制下一步一步构造，比一下子生成产品的模式更能反映构造过程

## 用法 (Usage)

### 适用场景

- 创建复杂对象的算法应独立于组成部分及装配方式
- 构造过程必须允许被构造对象有不同表示

### 参与者

- **Builder**：为创建Product对象的各个部件指定抽象接口
- **ConcreteBuilder**：实现Builder接口，定义所创建的表示，提供检索产品接口
- **Director**：构造使用Builder接口的对象
- **Product**：被构造的复杂对象

### 协作流程

1. 客户创建Director对象并用Builder对象配置
2. 导向器通知生成器生成产品部件
3. 生成器处理请求，将部件添加到产品
4. 客户从生成器检索产品

## 原理 (Principle)

### 分离分析算法和创建算法

Builder模式将分析文本格式的算法（RTF语法分析）与描述怎样创建和表示转换后格式的算法分离。可重用语法分析算法，根据不同Builder创建不同表示。

### 产品无抽象类

通常由具体生成器生成的产品，表示相差太大以至于给不同产品公共父类没有太大意义。客户知道哪个ConcreteBuilder被使用，能相应处理产品。

## 心法 (Best Practices)

### 实现要点

- Builder接口必须足够普遍，为各种类型的具体生成器构造产品
- C++中生成方法定义为空方法而非纯虚函数，客户只重定义感兴趣的操作
- 装配请求结果只是被添加到产品中，通常足够

### 与Abstract Factory对比

- Builder关注一步步构建复杂对象，最后返回产品
- Abstract Factory关注立即返回产品家族
- Builder更精细控制构造过程，Abstract Factory更关注产品组合

### 一句话总结

Builder是**分步构建复杂对象的分离器**——构造算法独立于表示，一步一步精细控制。
