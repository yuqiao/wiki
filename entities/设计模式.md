# 设计模式：可复用面向对象软件的基础

《设计模式：可复用面向对象软件的基础》（Design Patterns: Elements of Reusable Object-Oriented Software），俗称"GoF设计模式"，是软件工程领域的经典著作。由Erich Gamma、Richard Helm、Ralph Johnson、John Vlissides四位作者（合称"Gang of Four"）于1994年出版。

## 核心贡献

收录23个经典设计模式，系统性地命名、解释和评价面向对象系统中重复出现的设计问题。开创了设计模式运动的先河，成为程序员必读经典。

## 23个设计模式

### 创建型模式（Creational）—— 5个

| 模式 | 意图 |
|------|------|
| Abstract Factory | 提供创建一系列相关/依赖对象的接口，无需指定具体类 |
| Builder | 将复杂对象的构建与表示分离，同样构建过程可创建不同表示 |
| Factory Method | 定义创建对象的接口，让子类决定实例化哪个类 |
| Prototype | 用原型实例指定创建对象种类，通过拷贝原型创建新对象 |
| Singleton | 保证类仅有一个实例，提供全局访问点 |

### 结构型模式（Structural）—— 7个

| 模式 | 意图 |
|------|------|
| Adapter | 将类接口转换成客户期望的接口，使不兼容类可协同工作 |
| Bridge | 将抽象与实现分离，使两者可独立变化 |
| Composite | 将对象组合成树形结构表示"部分-整体"层次，统一对待单个和复合对象 |
| Decorator | 动态给对象添加额外职责，比子类更灵活 |
| Facade | 为子系统一组接口提供一致界面，定义高层接口使子系统更易用 |
| Flyweight | 运用共享技术有效支持大量细粒度对象 |
| Proxy | 为其他对象提供代理以控制访问 |

### 行为型模式（Behavioral）—— 11个

| 模式 | 意图 |
|------|------|
| Chain of Responsibility | 解除请求发送者与接收者耦合，多个对象有机会处理请求 |
| Command | 将请求封装为对象，可用不同请求参数化客户、排队、记录日志、支持取消 |
| Interpreter | 给定语言定义文法表示和解释器 |
| Iterator | 提供方法顺序访问聚合对象元素，不暴露内部表示 |
| Mediator | 用中介对象封装对象交互，使对象不需显式引用彼此 |
| Memento | 不破坏封装性前提下捕获对象内部状态并在外部保存 |
| Observer | 定义对象间一对多依赖，状态改变时所有依赖者得到通知 |
| State | 允许对象在内部状态改变时改变行为，看起来像修改了所属类 |
| Strategy | 定义一系列算法封装起来使它们可相互替换 |
| Template Method | 定义算法骨架，将一些步骤延迟到子类 |
| Visitor | 表示作用于对象结构各元素的操作，不改变元素类前提下定义新操作 |

## 设计模式四要素

1. **模式名称**：助记名，描述问题、解决方案和效果
2. **问题**：何时使用模式，解释设计问题和前因后果
3. **解决方案**：设计组成成分、相互关系、职责和协作方式
4. **效果**：模式应用效果和使用权衡

## MVC与设计模式

Smalltalk MVC是设计模式的经典案例，体现了三个核心模式：
- **Observer**：模型-视图的"订购/通知"协议
- **Composite**：视图嵌套，组合视图与构件平等对待
- **Strategy**：View-Controller关系，可替换响应策略

## 与SOLID原则的关系

设计模式是[[SOLID原则]]的具体实践：
- SRP体现于Facade、Bridge、Mediator
- OCP体现于Observer、Strategy、Decorator
- LSP体现于各类使用继承的模式
- ISP体现于Facade、Decorator
- DIP体现于Abstract Factory、Bridge、Strategy

## 历史影响

源自建筑师Christopher Alexander的模式思想（《建筑模式语言》），将"模式"概念引入软件领域。成为面向对象设计的基石，影响后续框架设计（如Java Swing、.NET Framework）。
